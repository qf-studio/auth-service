## Context

**Problem**: `/oauth/authorize`, `/oauth/token`, `/.well-known/openid-configuration`, `/userinfo` all 404. Pointer's SPA cannot do browser login against auth-service.

**Root cause** (verified 2026-07-26): the API layer is fully scaffolded but the services behind it were never implemented. Commit `08ead94` (GH-274, a decomposition child of the since-closed #27) landed:
- Handlers: `internal/api/oidc_handlers.go:12-94` (discovery/authorize/token/userinfo), `internal/api/admin_consent_handlers.go:18-171` (login/consent GET+PUT, ApproveClient)
- Interfaces + DTOs: `internal/api/services.go:140-277` (`OIDCProviderService`, `ConsentService`, `AdminClientApprovalService`, AuthorizeRequest with `code_challenge`, CodeExchangeRequest, OIDCTokenResponse, discovery doc, consent types)
- Conditional routes: `internal/api/router.go:68-86,161-171` and `internal/api/admin_router.go:202-217` — mounted only when the service interfaces are non-nil
- `cmd/server/main.go:153,229-230`: **nil placeholders, never assigned** → routes never mount → 404

**This task = implement the three service interfaces and wire them in `main.go`.** The HTTP contract is already fixed by the scaffolded handlers/DTOs/tests — implement to it, don't redesign it.

**Architecture** (matches the scaffolding and our adopted Hydra patterns, see `system/tech-decisions.md`):
Hydra-style challenge flow — auth-service holds no browser session and serves no HTML:
1. `GET /oauth/authorize` validates client_id/redirect_uri/scope/PKCE → creates a **login request** (challenge) → 302 to configured login UI (`?login_challenge=...`)
2. Login UI authenticates the user (existing `POST /auth/login`) then accepts the login request via admin API (`GET/PUT /admin/oauth/auth/requests/login`) → gets redirect back to authorize
3. Same dance for **consent** (`.../requests/consent`); first-party clients may auto-skip consent
4. Authorize issues a one-time **authorization code** → 302 to client redirect_uri
5. `POST /oauth/token` (grant_type=authorization_code) validates code + PKCE verifier (+ client secret for confidential clients) → access/refresh via existing `IssueTokenPair` (`internal/token/service.go:141`) + new **id_token**
6. `GET/POST /userinfo` serves claims from a valid access token

**Available building blocks**:
- `domain.Client.RedirectURIs` + `ClientTypePublic` (GH-436, migrations 000016/000017) — for redirect_uri validation and PKCE-required decisions
- `internal/oauth/pkce.go` `S256Challenge` — reuse for inbound verifier check (S256 only, per OAuth 2.1)
- Redis (go-redis) already in the stack — ephemeral stores
- `OIDCConfig` (`internal/config/config.go:49-54`: `IssuerURL`, `IDTokenTTL`, `SupportedScopes`) — loaded but currently dead; this task brings it live
- JWKS already public at `/.well-known/jwks.json` (`router.go:79`)

## Technical Decisions

| Decision | Options | Chosen | Reasoning |
|---|---|---|---|
| Login/consent UX | auth-service-hosted pages+cookies vs Hydra-style external UI + admin accept API | Hydra-style (external UI) | It's what the scaffolded handlers/routes already encode; no cookie/CSRF surface in auth-service; consumer (Pointer SPA) owns UX |
| Code/challenge storage | Postgres vs Redis | Redis, TTL + one-time | Ephemeral, short-lived, single-use; Redis already in stack; avoids table churn |
| Remembered consent | Redis vs Postgres | Postgres (000018) | Durable user decision; auditable; revocable |
| PKCE methods | S256+plain vs S256 only | S256 only | OAuth 2.1; `plain` is banned; helper exists |
| id_token signing | separate OIDC key vs existing JWT key | Existing key/kid | One JWKS, verifiers already fetch it; alg from existing config |
| Issuer source | keep const vs config with safe default | Config, default = current const | Unifies the known discrepancy without changing wire behavior by default |

**Scope guard**: no `response_type` other than `code`, no implicit/hybrid, no ROPC, no request objects/PAR/RAR wiring, no dynamic client registration, no front/back-channel logout, no `prompt=none` session checks. File follow-ups if wanted.
