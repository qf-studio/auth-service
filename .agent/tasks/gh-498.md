# GH-498

**Created:** 2026-08-31
**Status:** 🚀 Dispatched to Pilot (armed 2026-08-31 after #493/PR #500 merged)

## Problem

A3 of the E2E plan (`.agent/tasks/TASK-01-e2e-canary-strategy.md`): the MFA and OIDC golden paths on top of the A1 harness (#493).

## Context

Depends on the `e2e` package from #493. TOTP codes computable in-test with the same otp library the service uses (`github.com/pquerna/otp/totp`). OIDC flow requires `OIDC_LOGIN_UI_URL` set on the SUT (any URL — the test acts as the external UI by calling the admin PUT endpoints directly, mirroring `internal/oidc/oidc_flow_integration_test.go`'s flow but over real HTTP against the booted image).

**Execution-environment note**: without Docker locally, verify via `go build ./...` / `go test -short ./...` and rely on the e2e CI job.

## Task

1. **MFA flow**: register+login a user → MFA setup → confirm (TOTP computed in-test) → fresh login returns MFA challenge (no tokens) → complete via mfa verify endpoint → **fetch JWKS, parse and verify the access-token JWT, assert the roles claim is present and correct** (regression guard for GH-488) → backup-code login path once.
2. **OIDC flow**: create a client via admin API (with redirect URI) → `GET /.well-known/openid-configuration` (assert endpoints match the SUT's public base URL) → `/oauth/authorize` with PKCE S256 → follow the login-challenge redirect state via admin `PUT` login + consent (acting as the external UI) → exchange code at `/oauth/token` → validate ID token (`aud`, `nonce`, `iss`) → `GET /userinfo` with the access token.
3. Negative check folded in: authorization code single-use (second exchange fails).

## Acceptance criteria

- Both flows green in CI over real HTTP against the booted image (no in-process service construction).
- JWT assertions parse against the live JWKS endpoint, not a locally shared key.
- `go test -short ./...` clean without Docker; lint clean.

## Non-goals

Consent-remembering/approval edge cases; DPoP; logout-related OIDC semantics; wiring assertions (#494).
