# GH-495

**Created:** 2026-08-31
**Status:** 🚀 Dispatched to Pilot (armed 2026-08-31 after A1-A4 all merged)

## Problem

The E2E suite (issue A) only runs at PR time against a locally built image. Consumers (Pointer) and the canary (issue D) need a runnable verification artifact pinned to each release: when Pointer deployed v0.70.0 we could only read uptime off `/health` and guess whether migrations applied (#465). Strategy: `.agent/tasks/TASK-01-e2e-canary-strategy.md` (issue C).

## Context

- Release pipeline: `.github/workflows/release.yml` builds the multi-arch service image to GHCR on `v*` tags with a migration dry-run gate.
- The `e2e` package from issue A contains the flows; a subset of them is safe against a *live* deployment (no admin-port access, disposable identities).

## Task

1. **Smoke subset selection**: name the live-safe tests with a `TestSmoke` prefix (or equivalent `-run` filterable convention) inside the `e2e` package: health/readiness, discovery + JWKS shape, register→login→refresh→introspect→logout with a throwaway user (unique email per run), gRPC ValidateToken via `pkg/authclient`. Everything admin-port or destructive stays out.
2. **Smoke image**: compile the test binary (`go test -c ./e2e`) into a small runtime image (distroless or alpine) whose entrypoint runs the smoke filter. Config via env: `SMOKE_BASE_URL` (required), `SMOKE_GRPC_ADDR` (optional — skip gRPC tests when unset), `SMOKE_ADMIN_URL` (optional — enables the introspect leg when reachable). Exit code 0/1 = pass/fail; output is plain `go test -v` text.
3. **Publish**: extend `.github/workflows/release.yml` to build and push `ghcr.io/qf-studio/auth-service-smoke:<same version tag>` alongside the service image. Must not weaken the migration dry-run gate.
4. **Document**: usage section in `deployments/README.md` — one `docker run` example against a live URL, plus a note in the release notes template if one exists.

## Acceptance criteria

- `docker run --rm -e SMOKE_BASE_URL=http://host:4000 ghcr.io/qf-studio/auth-service-smoke:<tag>` passes against a locally composed stack and fails (non-zero, readable output) when the service is down.
- Smoke run creates only throwaway identities; running it twice in a row passes (idempotent).
- Release workflow publishes both images atomically for the same tag; CI green.

## Non-goals

The canary repo/cron that consumes this image (issue D); posting anything to #465 (Navigator does that once shipped); admin-port coverage in smoke mode.
