# GH-497

**Created:** 2026-08-31
**Status:** 🚀 Dispatched to Pilot (armed 2026-08-31 after #493/PR #500 merged)

## Problem

A2 of the E2E plan (`.agent/tasks/TASK-01-e2e-canary-strategy.md`): fake external services + the email-dependent golden paths, on top of the A1 harness (#493).

## Context

Depends on the `e2e` package from #493 (suite env struct, SUT container, `testing.Short()` convention). The SUT reaches host-side fakes via testcontainers host-port access (`host.testcontainers.internal`). Fake-service shape to follow: stateful struct + `httptest.NewServer` + method/path routing + assertion callback hooks (pattern proven in the pilot repo's e2e mocks).

**Execution-environment note**: without Docker locally, verify via `go build ./...` / `go test -short ./...` and rely on the e2e CI job.

## Task

1. **Mocks subpackage** inside the e2e directory:
   - `HIBPMock` — pwned-passwords range endpoint; configurable hit/miss per prefix.
   - `EmailSinkMock` — target for the HTTP email sender; captures messages, exposes helpers to extract reset/verify links.
   - `WebhookReceiverMock` — records deliveries; verifies `X-Signature-256` HMAC.
2. **Wire SUT env** to point HIBP/email at the mocks (host-port access), `EMAIL_ENABLED=true`.
3. **Flows**:
   - Full auth lifecycle: register → verify-email (link from EmailSinkMock) → login → refresh → admin `POST /admin/tokens/introspect` on the refresh token → `active:true` with correct `sub` → logout with `refresh_token` in body → introspect → `active:false`.
   - Password reset: request → link from EmailSinkMock → confirm → old password rejected on login, new accepted.

## Acceptance criteria

- Both flows green in CI; link extraction robust (no sleeps — poll the sink with timeout).
- WebhookReceiverMock lands with tests of its own even though no flow drives it yet (it's consumed by #494's wave-2 acceptance tests).
- `go test -short ./...` clean without Docker; lint clean.

## Non-goals

MFA/OIDC flows (#498); admin/gRPC flows (#499); wiring assertions (#494).
