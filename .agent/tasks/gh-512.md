## Problem

GitHub Issue GH-512: fix(tokens): refresh path drops per-client aud (falls back to global JWT_AUDIENCE) — must land before JWT_AUDIENCE_ENFORCE is flipped

## Problem

Post-merge review of PR #509 (issue #506): per-client `Audience` is applied on the OIDC code-exchange path (`internal/oidc/provider_service.go` ~242), but the refresh path in `internal/token/service.go` (~251-257) reissues the access token with a nil audience, which falls back to the global `JWT_AUDIENCE`. For a client with a distinct audience, the first refreshed token carries the wrong `aud`. Harmless while `JWT_AUDIENCE_ENFORCE=false`; the moment a product flips enforcement, its sessions break on first refresh.

Also from the review: password/MFA login paths (`internal/auth/service.go` ~382, `internal/mfa/mfa.go` ~309) issue with global audience because they have no client context, and the root `README.md` still documents nothing about `Audience` / `JWT_AUDIENCE_ENFORCE` (only `deployments/README.md` does).

## Task

1. Refresh: resolve the client for the refresh token (the refresh record or session already knows the client id) and pass `client.Audience` to reissue, same fallback rule as issuance (empty → global).
2. Password/MFA login: if a client id is available on the request/session, apply the same rule; if genuinely no client context exists, document that these flows issue global-audience tokens and are not usable with per-client enforcement.
3. Root `README.md`: document `Audience` on clients, `JWT_AUDIENCE`, and `JWT_AUDIENCE_ENFORCE`, and the integration order (set client audience → verify tokens → flip enforcement at the resource server).

## Acceptance

- Test: client with audience X → login → refresh → refreshed access token `aud` contains X (not the global value).
- Test: client without audience → refresh → global audience (unchanged behaviour).
- README section present; `deployments/README.md` cross-links it.

This must land before any product sets `JWT_AUDIENCE_ENFORCE=true`.
