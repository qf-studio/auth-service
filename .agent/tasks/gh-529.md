# GH-529

**Created:** 2026-10-27

## Problem

GitHub Issue GH-529: fix(sessions): replace the in-process session store; terminating sessions revokes tokens

## Context
`cmd/server/main.go` ~line 144 uses `session.NewMemoryStore()` (documented for development only). Prod runs several tasks, so `GET /auth/sessions` shows a random subset and `DELETE /auth/sessions` only edits one process's map; it revokes no tokens. Login ignores the `CreateSession` error (`internal/api/auth_handlers.go` ~line 60) and the MFA login path creates no session.

## Implementation Plan

1. Redis-backed `session.Store` in `internal/session` (keys per user with TTL = refresh TTL), wired in `cmd/server/main.go`.
2. Create the session in both password and MFA login paths; log (not ignore) store errors.
3. `DELETE /auth/sessions` (terminate all) also calls the auth service's `LogoutAll` path (which revokes refresh tokens through the refresh-token repository) — reuse it, do not duplicate revocation logic.
4. Remove `MemoryStore` from non-test code, or keep it only for tests.

## Technical Decisions

Reuse the existing LogoutAll revocation path; no second revocation mechanism.
