## Acceptance

- Unknown or already-consumed confirm and revert tokens answer 400 with the existing error shape, never 404. In `internal/api/auth_handlers.go` the ConfirmEmailChange and RevertEmailChange handlers map the not-found error from ConsumeEmailChangeToken and ConsumeEmailRevertToken to http.StatusBadRequest with code bad_request (the same status the VerifyEmail handler uses for a bad token); expired stays 410. `internal/api/router_test.go`: TestConfirmEmailChange_UnknownToken and TestRevertEmailChange_UnknownToken assert 400; add TestConfirmEmailChange_ConsumedToken (second confirm with the same token → 400) at the service level in `internal/auth/service_test.go` using the mock repository's not-found path.
- The per-user rate limit counts every request, not only successful ones. In `internal/auth/service.go` RequestEmailChange calls checkEmailChangeRateLimit first, before the password check and before the same-address and taken-address checks; the fourth call in the window answers the 429-class error regardless of the password. Test in `internal/auth/service_test.go`: three wrong-password calls followed by one correct call → rate-limited error, zero mails sent.
- checkEmailChangeRateLimit issues INCR and EXPIRE in one pipeline (TxPipeline or Pipelined on the existing Redis client), the way AccountRateLimiter.RecordFailure does in `internal/middleware/ratelimit.go`, so a key can never exist without a TTL. TestRequestEmailChange_RateLimited additionally asserts the key's TTL is greater than zero and at most one hour after the first call.
- An end-to-end case covers request → confirm → the old refresh token is rejected: either in `internal/api/auth_integration_test.go` (mock-backed, runs in the test job) asserting RevokeAllForUser was called exactly once with the user's tenant and id and that a refresh with the old token afterwards answers 401, or in `e2e/email_lifecycle_test.go` against the real stack. One of the two, not a skipped test.
- go vet, spectral and the full suite green; no change to `api/public.openapi.yaml` (it already documents 400/409/410 for confirm and revert).
