# GH-493

**Created:** 2026-08-31
**Status:** 🚀 Dispatched to Pilot
**Pilot issue:** https://github.com/qf-studio/auth-service/issues/493

## Problem

Nothing tests the real binary. `cmd/server` has zero test files; every test bypasses the `main()` wiring and hand-wires mocks. Review-003 (2026-08-30) found 25+ defects of exactly the class this hides: services constructed but never registered, nil repos injected, config read but never passed, a table with no migration. Full strategy: `.agent/tasks/TASK-01-e2e-canary-strategy.md` (this issue = layer L1, issue A).

## Context

- Existing partial coverage: `internal/oidc/oidc_flow_integration_test.go` (testcontainers, but constructs services itself — does not exercise `main()`), `internal/storage/repository_integration_test.go` (repo layer), `migrations/consent_grants_migration_test.go`.
- The image (`docker/Dockerfile`) ships `/auth-service` (entrypoint) and `/auth-migrate`; ports 4000 (public), 4001 (admin), 4002 (gRPC). Server config is env-driven (`internal/config/config.go`) — DB/Redis DSNs, `SYSTEM_SECRETS`, JWT key path, `OIDC_ISSUER_URL`, `OIDC_LOGIN_UI_URL`, `EMAIL_ENABLED` + HTTP sender URL.
- SDK: `pkg/authclient` (gRPC).
- Pattern sources in the pilot repo (read before implementing): fake-external-service shape in pilot's e2e mocks (stateful struct + `httptest.NewServer` + method/path routing + assertion callback hooks), obviously-fake secret constants convention.

## Task

Create a new top-level Go package named `e2e` (own directory at repo root) containing a black-box harness plus the P0 golden-path suite. Every test guarded by `testing.Short()` — no build tags.

1. **Harness**:
   - testcontainers-go: postgres + redis module containers on a shared network.
   - SUT container from the service image: use `E2E_IMAGE` env when set (CI builds and passes it), else build from `docker/Dockerfile` via testcontainers' from-Dockerfile support.
   - Generate an ES256 private key in a temp dir at test start; mount into the SUT container; wire the key-path env.
   - Run migrations before server start: same image, entrypoint overridden to `/auth-migrate`, arg `up` (mirrors the release CI dry-run job in the release workflow).
   - Readiness: poll `/readiness` on the public port until 200 (bounded).
   - Host-side fake externals must be reachable from the container: use testcontainers host-port access (`host.testcontainers.internal`).
2. **Fake externals** (subpackage `mocks` inside the e2e directory, pilot shape): `HIBPMock` (range-query endpoint), `WebhookReceiverMock` (records deliveries, verifies `X-Signature-256`), `EmailSinkMock` (HTTP sender target; captures reset/verify links for extraction). Stateful, mutex-guarded, assertion hooks.
3. **Fake secrets**: obviously-fake constants (e.g. `test-system-secret`) in one file; nothing that trips push-protection.
4. **P0 golden paths** (all over real HTTP/gRPC, no in-process shortcuts):
   - a. register → verify-email (link from EmailSinkMock) → login → GET `/me` → refresh → admin `POST /admin/tokens/introspect` shows refresh `active:true` → logout (with refresh_token in body) → introspect `active:false`
   - b. MFA: setup → confirm (TOTP computed in-test) → login returns challenge → verify → parse the access-token JWT against JWKS and assert the roles claim
   - c. Admin: create client → rotate secret (old works during grace) → create API key → validate (via whatever endpoint consumes API keys; if none is wired, validate via the admin service path and note it) → rotate → revoke → rejected
   - d. OIDC: discovery → JWKS → `/oauth/authorize` → admin PUT login + consent (acting as the external UI) → code → `/oauth/token` → `/userinfo`
   - e. gRPC via `pkg/authclient`: ValidateToken (valid + garbage), IntrospectToken, GetUser
   - f. password reset: request → link from EmailSinkMock → confirm → old password rejected, new accepted
5. **Retrofit**: add the same `testing.Short()` guard to `internal/oidc/oidc_flow_integration_test.go` (currently hard-fails without Docker).
6. **CI**: new job in the test workflow: build the image, then `go test ./e2e/ -v -timeout 20m` with `E2E_IMAGE` set. 20m is deliberate 2× headroom (pilot GH-5185 lesson: shared runners run hot). The job must be required — not optional, not a separate local-only target.

## Technical Decisions

- Boot the **image**, not a compiled binary: catches Dockerfile/entrypoint/env regressions (the class that broke `scripts/deploy.sh` and the port-4002 gap).
- `testing.Short()` over build tags: one mechanism repo-wide; plain `go test ./...` includes E2E when Docker is present, `-short` skips cleanly.
- stdlib HTTP + testify only; gRPC through `pkg/authclient` so SDK breaks fail E2E.

## Acceptance criteria

- All P0 paths green locally (`go test ./e2e/ -v`) and in the new CI job.
- `go test -short ./...` passes with no Docker daemon available.
- Each flow asserts response bodies/claims, not just status codes (e.g. introspect `sub`/`exp`, JWT roles).
- Harness teardown leaves no containers behind (t.Cleanup / reaper).
- `golangci-lint run` clean; existing suites unaffected.

## Non-goals

Wiring assertions & skipped wave-2 acceptance tests (issue B); smoke-image publishing (issue C); canary repo (issue D); fault injection / TLS-proxy scenarios; staging.
