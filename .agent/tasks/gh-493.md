## Problem

Nothing tests the real binary. `cmd/server` has zero test files; every test bypasses the `main()` wiring and hand-wires mocks. Review-003 (2026-08-30) found 25+ defects of exactly the class this hides. Strategy: `.agent/tasks/TASK-01-e2e-canary-strategy.md`.

**Scope note**: this issue is A1 — the harness foundation ONLY. The remaining golden-path flows are follow-up issues (A2 #497, A3 #498, A4 #499), armed sequentially after this merges. Do not implement them here; the previous, wider version of this issue timed out twice at the 1h cap.

## Context

- The image (`docker/Dockerfile`) ships `/auth-service` (entrypoint) and `/auth-migrate`; ports 4000 (public), 4001 (admin), 4002 (gRPC). Server config is env-driven (`internal/config/config.go`).
- Reference for booting deps in tests: `internal/oidc/oidc_flow_integration_test.go` already uses testcontainers postgres/redis modules (but self-wires services — do not copy that part).
- **Execution-environment note**: if Docker is not available where you run, do NOT attempt to execute the e2e tests locally — verify with `go build ./...`, `go vet ./...`, `go test -short ./...`, and rely on the new CI job for e2e validation.

## Task

Create a new top-level Go package named `e2e` (own directory at repo root). Every test guarded by `testing.Short()` — no build tags.

1. **Harness** (the bulk of this issue):
   - testcontainers-go postgres + redis containers on a shared network.
   - SUT container from the service image: use `E2E_IMAGE` env when set (CI builds and passes it), else build from `docker/Dockerfile` via testcontainers' from-Dockerfile support.
   - Generate an ES256 private key in a temp dir at suite start; mount into the SUT container; set the key-path env var.
   - Migrations before server start: same image, entrypoint overridden to `/auth-migrate`, arg `up`.
   - Readiness: poll `/readiness` on the public port until 200 (bounded, fail fast with container logs on timeout).
   - Expose a small suite API (e.g. a `TestMain`-managed shared env struct with base URLs) that follow-up issues A2–A4 can add flows onto without touching harness internals.
   - Fake-secret constants in one file (obviously fake values only — push-protection).
2. **First golden-path flow** (proves the harness end to end): register → login → GET `/me` → refresh → logout, over real HTTP, asserting response bodies (user id, token prefixes `qf_at_`/`qf_rt_`), not just status codes.
3. **CI job**: new job in the test workflow: build the image, `go test ./e2e/ -v -timeout 20m` with `E2E_IMAGE` set. Required job, not optional.
4. **Retrofit**: add a `testing.Short()` guard to `internal/oidc/oidc_flow_integration_test.go` so `go test -short ./...` passes with no Docker daemon.

## Technical Decisions

- Boot the **image**, not a compiled binary — catches Dockerfile/entrypoint/env regressions.
- `testing.Short()` over build tags: one mechanism repo-wide.
- stdlib HTTP + testify only.

## Acceptance criteria

- The flow in (2) green in the new CI job.
- `go test -short ./...` passes without Docker.
- Harness teardown leaves no containers (t.Cleanup/reaper).
- `golangci-lint run` clean; existing suites unaffected.

## Non-goals

Email/HIBP/webhook mocks and the remaining flows (A2 #497, A3 #498, A4 #499); wiring assertions (#494); smoke image (#495); canary (#496).
